Get started

Install Git and Node.js 22.13 or newer. From your own Git clone, install the release package or replace its name with the path to a pre-release archive.

npm install -D @tobiasoberpaul/aip
npm exec -- aip serve

Open the printed loopback URL. For regular package updates, run npm update @tobiasoberpaul/aip. To run directly from source instead, use the tool repository:

git clone https://github.com/Tobias-Oberpaul/aip.git
cd aip
npm ci
npm start -- "<path-to-your-project-clone>"

How collection starts

Installing the package leaves collection off. Enable the hooks you want in your own clone:

npm exec -- aip init --codex
npm exec -- aip init --kiro
# Or enable both with init --codex --kiro

Codex users also review the new hooks in Settings → Hooks. Each clone opts in separately, even when the team shares hook configuration. Run npm exec -- aip disable to pause collection by the npm hooks. The steps below also describe manual setup when running from source.

If you installed the previous package, @tobiasoberpaul/ai-performance, install @tobiasoberpaul/aip first. Run aip init with the same provider options before uninstalling the old package. This updates the launchers and keeps your local database.

Codex

  1. Copy the scripts from tool/telemetry/.codex/hooks/ into .codex/hooks/ in your project. Merge the entries from tool/telemetry/.codex/hooks.json into your project's .codex/hooks.json.
  2. Review and trust the hooks in Codex under Settings → Hooks or with /hooks in the CLI. Use your own local hook configuration when deciding whether to collect usage.
  3. Work in Codex. The usage hook records available token counts per model attempt. The history hook saves available start context, timing and quota measurements at turn completion, interruption and session end.

Kiro

  1. Copy tool/telemetry/.kiro/hooks/ into .kiro/hooks/ in your project. Copy performance-store.cjs and performance-backup.cjs from tool/telemetry/.codex/hooks/ into your project's .codex/hooks/.
  2. Start a Kiro session in the clone. The AgentStop hook records the completed run as Kiro. To associate runs with a known ticket at capture time, set AI_PERFORMANCE_TICKET_ID in the environment that starts Kiro.
  3. Supply measured per-run credits through the record command when you have a source for them. Account and pool balances have separate records.

Connect a run to a ticket

Give each ticket a stable ID, a name and an epic. Add a text description with the goal, context and expected result. Keep new work within one chat per ticket. Link a Codex turn by its session ID and turn ID in the ticket's subtasks. Each Codex turn can belong to one ticket. For Kiro, use a ticket ID during capture or list unassigned runs with npx aip record list unassigned and link one using its provider/id.

Define epic names in the project index CONTEXT.md and keep agent instructions in AGENTS.md. Run npx aip init --context to add this setup on its own. Use npx aip context epic "Epic name" to add a new area and npx aip record list ticket to inspect existing tickets.

npm run record -- ticket ticket.json "<path-to-your-project-clone>"

The ticket view adds up recorded work time and shows tokens and credits in their original units. Missing measurements are marked in the ticket details.

See the record command reference for JSON examples.

Read the dashboard

The visible dashboard checks for updates every 15 seconds and when you return to its tab. Filter tickets by epic and story points, or sort by recorded effort. Open a ticket for its description, measurements and work history.

The two headline values show project-wide tokens and work time per story point. Below 25% context, their badges compare the last measured chat with the rest of the project. At 25% and above, the badges compare recent tickets in that chat with its earlier tickets. Each comparison needs at least five measured tickets per group and metric.

Open Documentation to read the project's CONTEXT.md and linked notes. On a subpage, Back opens the previous page. The breadcrumb gives you direct access to earlier pages in the path.

What stays in your clone

Each local clone has its own .codex/performance.sqlite. The npm initializer adds the following rules. For manual setup, add them to .gitignore or .git/info/exclude before enabling collection.

/.codex/performance.sqlite*
/.codex/backups/
/.codex/performance-backup-*.error
/.codex/context-packages.json
/.codex/context-usage.jsonl
/.codex/context-history/
/.codex/ai-performance-enabled.json

The database contains ticket metadata, tool and model names where available, run references, timings, and usage and quota measurements. The supplied hooks omit prompt text, replies and tool output. GitHub Pages publishes this guide. Your dashboard is served on your computer.

Everyone using a separate clone gets a separate database. People with access to the same checkout can access its database.

Migrate and back up your data

On first open, the tool copies legacy ticket data, usage logs and saved measurements into SQLite. To capture measurements still available in Codex history, run the import from the tool directory before deleting old chats.

npm run import-history -- "<path-to-your-project-clone>"

Saved measurements remain available after their source chat is removed. AIP keeps verified daily snapshots and a rolling latest.sqlite in .codex/backups/. List available snapshots, then preview the one you want to restore.

npx aip backup list
npx aip backup preview latest.sqlite
npx aip backup restore latest.sqlite <version-from-preview>

From the tool clone, use npm run backup -- followed by the same subcommand. Restore saves the previous database contents as an undo snapshot and prints its name.
